# PowerShell & SQLite — Comprehensive Example Guide

A fully self-contained, portable, and production-ready reference project demonstrating how to use **SQLite** in **PowerShell 5.1** (Windows PowerShell) and **PowerShell 7+** (PowerShell Core).

---

## Key Benefits of SQLite in PowerShell

| Feature | Plain JSON / CSV Files | SQLite Database |
| :--- | :--- | :--- |
| **Integrity & ACID** | Prone to corruption during partial writes | Full ACID transactions (`COMMIT` / `ROLLBACK`) |
| **Concurrency** | File locking conflicts on write | WAL mode enables concurrent readers and writers |
| **Performance** | Reading 100k rows parses entire file | B-tree indexes provide millisecond point lookups |
| **Bulk Writes** | Rewrite entire file on any change | Ingest thousands of rows/sec with BulkCopy |
| **Queries** | Slow in-memory filtering via pipeline | Standard SQL with joins, aggregations & group by |
| **Dependencies** | Built-in | Self-contained single-file database (`.db`) |

## Core Concepts & Code Snippets

### 1. Connecting to an SQLite Database
SQLite databases are single portable `.db` or `.sqlite` files. You can also use in-memory databases (`:memory:`):

```powershell
Import-Module (Join-Path $PSScriptRoot 'SQLiteHelper.psd1')

# Connect to file database and enable WAL mode
$dbPath = 'C:\Data\inventory.db'
Connect-SqliteDb -DataSource $dbPath -EnableWal
```

### 2. Creating Tables & Indexes
```powershell
$sql = @"
CREATE TABLE IF NOT EXISTS Servers (
    Id          INTEGER PRIMARY KEY AUTOINCREMENT,
    HostName    TEXT NOT NULL UNIQUE,
    IPAddress   TEXT NOT NULL,
    Environment TEXT NOT NULL,
    Cores       INTEGER NOT NULL,
    RAM_GB      REAL NOT NULL,
    LastAudit   TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_servers_env ON Servers(Environment);
"@

Invoke-SqliteCmd -DataSource $dbPath -Query $sql
```

### 3. Secure Parameterized Queries (Anti-SQL-Injection)
Never concatenate untrusted user input into SQL queries. Always use SQLite parameters (`@ParamName`):

```powershell
$params = @{
    HostName    = 'SKATFS01'
    IPAddress   = '192.168.10.25'
    Environment = 'Production'
    Cores       = 16
    RAM_GB      = 64.0
    LastAudit   = (Get-Date -Format 'o')
}

$insertSql = @"
INSERT INTO Servers (HostName, IPAddress, Environment, Cores, RAM_GB, LastAudit)
VALUES (@HostName, @IPAddress, @Environment, @Cores, @RAM_GB, @LastAudit);
"@

Invoke-SqliteCmd -DataSource $dbPath -Query $insertSql -SqlParameters $params
```

### 4. Reading Data as PowerShell Objects
`Invoke-SqliteCmd` automatically maps SQLite rows to PowerShell `PSCustomObject` instances, enabling familiar pipeline operations:

```powershell
$prodServers = Invoke-SqliteCmd -DataSource $dbPath `
    -Query "SELECT HostName, IPAddress, RAM_GB FROM Servers WHERE Environment = @Env ORDER BY RAM_GB DESC;" `
    -SqlParameters @{ Env = 'Production' }

$prodServers | Format-Table -AutoSize
$prodServers | Where-Object { $_.RAM_GB -gt 32 } | Export-Csv -NoTypeInformation 'HighRAM.csv'
```

### 5. High-Speed Transactions
SQLite writes to disk with sync locks by default. Executing 500 inserts without a transaction performs 500 disk syncs. Inside an explicit transaction, all 500 inserts execute in memory with a single disk sync:

```powershell
Invoke-SqliteTransaction -DataSource $dbPath -ScriptBlock {
    param($conn)
    foreach ($item in $bulkItems) {
        Invoke-SqliteCmd -SQLiteConnection $conn -Query $insertSql -SqlParameters $item | Out-Null
    }
}
```
> [!TIP]
> Wrapping multi-row inserts in `Invoke-SqliteTransaction` improves insertion performance by **10x to 100x**!

### 6. Streaming PowerShell Objects with BulkCopy
To ingest hundreds or thousands of live PowerShell objects (such as `Get-Service`, `Get-Process`, or CSV data) at native speed:

```powershell
# 1. Collect objects
$services = Get-Service | Select-Object Name, Status, StartType

# 2. Convert to DataTable
$dt = $services | Out-DataTable

# 3. Stream directly into SQLite table
Invoke-SqliteBulkCopy -DataTable $dt -DataSource $dbPath -Table 'SystemServices' -ConflictClause Replace -Force
```

### 7. Database Maintenance & Compaction
```powershell
# Verify B-tree and page integrity
$status = Invoke-SqliteCmd -DataSource $dbPath -Query "PRAGMA integrity_check;" -AsScalar
Write-Host "Integrity status: $status" # Expected: 'ok'

# Reclaim free space after deleting rows
Invoke-SqliteCmd -DataSource $dbPath -Query "VACUUM;"
```

## Cross-PowerShell Compatibility Guide

1. **PowerShell 5.1 (.NET Framework)**:
   - Uses `lib\PSSQLite\x64\System.Data.SQLite.dll` (or `x86`).
   - SQLite 3.8.8.3 engine.
   - Use `INSERT OR REPLACE INTO ...` for cross-version upsert support.
   - Use `ConvertTo-Csv` when capturing CSV strings in pipelines.

2. **PowerShell 7+ (.NET Core)**:
   - Uses `lib\PSSQLite\core\win-x64\System.Data.SQLite.dll`.
   - SQLite 3.30.1 engine.
   - Fully supports modern SQLite syntax.

3. **Character Encoding**:
   - All PowerShell source files (`.ps1`, `.psm1`, `.psd1`) and generated reports (`.csv`, `.json`, `.md`) are encoded in **UTF-8 with BOM** (`0xEF, 0xBB, 0xBF`) to ensure cross-edition Polish diacritic preservation.
